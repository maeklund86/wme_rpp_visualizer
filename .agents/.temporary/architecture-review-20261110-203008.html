Candidate 01

Deepen the refresh-trigger module

Strong in-process

Files: WME_RPP_Visualizer.js, src/wme-segment-refresh-events.js, src/annotation-refresh-lifecycle.js, tests/wme-segment-refresh-events.test.js

Problem

The segment helper only filters event payloads. Map, venue, and SDK registration stays in the entry module, so tests do not cover a refresh hint from source to lifecycle.

Solution

Gather refresh-source registration and hint routing behind one module. Keep debounce, coalescing, threshold checks, and failure recovery in the existing lifecycle module.

  • Locality: event changes stay together
  • Leverage: one path serves three sources
  • Tests cover registration through refresh
  • Preserve lifecycle depth

Candidate 02

Give WME snapshots one owner

Worth exploring local-substitutable

Files: src/wme-annotation-refresh-host.js, src/annotation-construction.js, src/openlayers-annotation-adapter.js, tests/annotation-construction.test.js

Problem

WME entry point shapes are interpreted in both the refresh host and annotation construction. Segment snapshot conversion sits in the OpenLayers adapter, so WME format changes cross unrelated seams.

Solution

Give WME venue, entry point, and Road segment normalization one owner. Keep annotation construction on plain snapshots and keep OpenLayers projection and materialization separate.

  • Locality: WME shape changes stay together
  • Tests focus on snapshot normalization
  • Construction reads stable domain data
  • OpenLayers seam has one purpose

Top recommendation

Start with the refresh-trigger module

Recent changes repeatedly add refresh sources, while the existing helper tests only payload filtering. Deepening this seam gives the changed area locality and lets tests verify the event path without changing the already-deep refresh lifecycle.
